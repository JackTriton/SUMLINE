# SUMLINE v1.4 構成と通信先

## 構成

| 機能 | 実装 |
| --- | --- |
| ゲーム画面 | HTML/CSS/JavaScript。配布物の静的ファイルから読み込む |
| タップ判定 | public/input.js。単タップを保留してダブルタップと区別し、スクロールや中断時はキャンセル |
| レスポンシブ表示 | public/mobile.css。画面幅と操作方法に応じた盤面・フォーム・メニュー |
| 盤面生成 | ブラウザーのWorker。設定したシードから生成し、一意解を検証 |
| オフライン記録・設定 | ブラウザーのローカルストレージ |
| 音とスキン | ブラウザー内の音声合成と色設定。外部素材の取得は不要 |
| オンラインID | 共有APIで発行する256ビットのランダムトークン。サーバーはSHA-256ハッシュを保持 |
| ランキング・大会 | 共有APIとSQLデータベース |
| ローカル起動 | Node.js標準ライブラリーのHTTPサーバー。既定はループバック接続 |
| 静的公開 | GitHub Pagesや任意の静的Webサーバー |

## 実行時の通信

`pages.config.json`の`apiBase`が空欄なら、ゲームは配信元の静的ファイルだけを読み込みます。API用のリクエストは送信しません。分析SDK、外部フォント、外部音源、広告スクリプトは組み込んでいません。

共有APIを設定した場合は、そのURLに以下の要求を送ります。

| 操作 | API | 内容 |
| --- | --- | --- |
| オンラインID作成 | POST guest | 本人識別用トークンの発行 |
| 接続状態確認 | GET me | ID、表示名、受理済みの通常進行 |
| 表示名更新 | POST profile | 入力したユーザー名 |
| 記録対象の開始 | POST session | モード、コース、盤面番号、表示名、提供同意 |
| クリア記録提出 | POST submit | セッションID、確定操作の履歴、提供同意 |
| ランキング閲覧 | GET ranking | 期間、対象大会、盤面別記録 |
| 大会作成・閲覧 | POST/GET tournaments | 大会名、シード、サイズ、開催期間、盤面数 |

IDはAuthorizationのBearerトークンとして送ります。利用者が送った別のユーザーIDヘッダーを認証の根拠にせず、DBでトークンを照合して本人を決定します。

## 配備

静的ファイルと共有APIは別々に配備できます。外部APIにはHTTPSを使い、APIの許可Originには実際のフロントエンドの公開元を登録してください。管理用キーをフロントエンドの設定へ書き込む必要はありません。

GitHub Pages用のActionsとローカル起動の手順を含め、ルートREADMEと公開ガイドから再構築できます。特定の生成環境や開発用ホストへの依存はありません。

## 記録と保存

再挑戦、カスタム、接続を失った挑戦はオンラインランキングの対象外です。送信失敗時に自動で再送するキューはありません。共有APIを設定していない利用者も、端末内のゲーム機能を利用できます。

専用IDはブラウザー単位です。同期可能なアカウントが必要な場合は、メールやパスキーなどの認証基盤を別途追加する設計です。現行の検証はカジュアルなランキング向けで、自動解法の完全な排除は保証しません。


## 日本語・英語表示

画面上部または設定から日本語・英語・端末に合わせた自動表示を選べます。`public/i18n.js` と `public/messages.js` を同梱します。言語設定はサイトごとに保存し、従来の盤面・記録・スキン・オンラインIDを維持します。日付とランキングの集計はJST固定です。詳細は[多言語対応ガイド](LANGUAGES.md)を参照してください。
